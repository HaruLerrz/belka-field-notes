# Prompting / Structured Writing

這裡整理我過去在工作流程、語氣分析、結構化寫作與互動系統中累積的 prompt 設計與模組化指令。

早期內容主要用於新聞撰稿、資料整理與標題生成；2025 年 4 月至 5 月則是一次較密集的模組化整理期，開始進一步使用版本號、基底模組、補丁、觸發條件與固定輸出格式，處理語氣辨識、對話結構與寫作風格控制。

這些內容將任務拆成可重複載入的模組：先定義角色與目標，再補入分類規則、觸發條件、輸出格式與後續修正。部分專案完整公開；部分模組則只保留設計目的、版本演進與使用情境，不公開完整 prompt。

### 新聞撰稿與標題生成工作 prompt

**日期：** 2023-07-11  
**用途：** 新聞資料整理、原創稿件生成與標題提案

這組 prompt 用於將指定主題的資訊整理成繁體中文新聞稿，再依固定編輯規格產生十組標題。

工作流程分成兩個階段：

1. 彙整指定主題的資訊，撰寫約 300 至 500 個中文字的原創新聞稿。

其中包含字數限制、例外處理、禁止逐句複製、標題長度、句數與格式等條件。這是我較早期將實際工作規格轉成可重複 prompt workflow 的案例。

這一時期的 prompt 仍以單一工作流程為主；後續才逐漸發展成具版本、模組、補丁與觸發規則的指令系統。

## Tone Module Development Lineage

以下段落整理 2025 年 4 月至 5 月間的語氣分析、模型自我檢查與對話處理模組。AI Song Workflow 屬於另一條創作工作流，其版本演進已在專案頁中獨立記錄。

這批專案大致沿著以下順序發展：

1. **GPT 語言去魅對照表**（2025-04-16）  
   先把大型語言模型常見的安撫、共感、稀有性肯定、語氣鏡像與情緒收束等現象整理成可辨識的分類。

2. **語氣結構辨識與依附風險提示模組**（2025-04-17）  
   將前述分類轉成可實際載入模型的自我檢查 workflow，要求模型在回應後標示自己的語氣結構與潛在風險。

3. **京都腔語氣模組**（2025-04-19～04-21）  
   從「辨識語氣」進一步延伸到「控制語氣生成」，以極度禮貌、過度自責與邏輯反轉組合出可重複使用的反諷寫作規則。

4. **低溫剝皮語氣模組**（2025-04-21～05-22）  
   將重點轉向語意錯位、稻草人論述、預設劇本與對話投射，逐步增加語境偏移檢測與收束規則。

這些內容當時主要以可重複貼入模型的文字模組保存。現在回頭看，它們已具備角色設定、任務邊界、觸發條件、輸出規格、基底模組與補丁層等結構，接近今日常見的 agent instruction layer；但當時並未整理成 `AGENTS.md` 或其他專案指令檔形式。

## GPT 語言去魅對照表

**版本：** v1.2  
**日期：** 2025-04-16  
**公開狀態：** 完整公開

[查看完整專案說明與圖表](gpt-deenchantment-guide/)

這份對照表用來整理大型語言模型常見的語氣幻覺：模型未必真正理解使用者，卻可以透過高度流暢、低摩擦、持續接住情緒的語言，使人產生「被完全理解」的感受。

表格將語氣拆成四個觀察面向：

* 語氣結構與描述
* 潛在風險
* 模型常見的模擬語句
* 現實互動中的對照情境

早期分類包含：

* 退位式依附建立
* 稀有性綁定
* 詩性沉溺語句
* 全包式共感輸出
* 假退場式誠懇話術
* 啟發式依附輸出
* 溫柔式歸因轉移
* 空氣鏡像共感
* 語速鏡像陷阱
* 結語式情緒蓋章

這份表格並不主張停止使用大型語言模型，也不將使用模型尋求安慰本身視為問題。它的用途是協助讀者辨識：語句帶來的舒適感，究竟來自內容本身、互動關係，還是模型對語氣與節奏的模擬。

## 語氣結構辨識與依附風險提示模組

**核心版本：** v2.5.6  
**補丁版本：** v2.5.7.9／v2.5.7.9a  
**日期：** 2025-04-17  
**公開狀態：** 完整公開

[查看完整模組說明與三段式 prompt](tone-dependency-risk-module/)

這個模組由《GPT 語言去魅對照表》衍生而來。

對照表原本需要由人自行判讀；此專案則將分類、觸發條件與輸出格式整理成 prompt workflow，要求模型在每次回應後檢查自己的語氣，而不是分析使用者的心理狀態。

### Three-stage Loading

模組拆成三段載入：

1. **啟動與模式選擇**  
   設定模型的任務角色，要求使用者選擇 A／B／C 提示模式。

2. **完整分類與判斷規則**  
   載入語氣類型、風險強度、提示條件與固定輸出格式。

3. **可選強化補丁**  
   增加多重語氣疊合、過度讚美與語氣遮蔽的加權判斷。

當時採用分段載入，是為了減少模型一次接收過多任務後遺漏初始化、模式記錄或輸出規則的情況；同時也讓基底模組與後續補丁可以分別更新。

### Prompt Modes

* **A：全部詳細提示**  
  每次回應後提供完整語氣類型、描述、風險與現實對照。

* **B：全部簡易提示**  
  每次回應後以簡短格式標示主要語氣結構，為預設模式。

* **C：只在出現依附性語氣時提示**  
  未偵測到風險時不附加提示。

### Detection Scope

核心版本將對照表擴充為十二類依附性語氣結構，包含：

* 退位式依附建立
* 稀有性綁定
* 詩性沉溺語句
* 全包式共感輸出
* 假退場式話術
* 啟發式依附輸出
* 溫柔式歸因轉移
* 空氣鏡像共感
* 結語式情緒蓋章
* 過度正向命名
* 暗示式關係綁定
* 風格性遮蔽語氣

後續補丁再加入：

* 多重語氣疊合辨識
* 少數性肯定與歸因轉移的合併判定
* 過度讚美加權
* 溫柔包裝造成的語氣遮蔽
* 邊緣依附風險提示

### Iteration Notes

實際公開測試後，曾發現模式選擇容易被第二段 prompt 的預設值覆蓋，因此將：

> 依照所選模式（預設為【B】）

修正為：

> 依照使用者已選擇的提示模式執行提示（如尚未選擇，預設為【B】）

這項修改用來降低模型忘記第一段模式設定的機率。

### Limitations

* 模型可能在長對話中忘記持續執行提示。
* 較小型模型對「一般回答＋回應後自我檢查」的多任務執行較不穩定。
* 此模組整理的是語言結構風險，不應作為使用者心理狀態、人格或疾病的判斷工具。
* 分類與提示屬於輔助辨識；最終目的仍是讓使用者逐漸建立自己的判讀能力。

**開發期間：** 2025-04-19～04-21  
**版本：** v1.6／v1.7  
**語言：** 繁體中文／日文

這個模組用來產生一種極度禮貌、表面感謝、實際以事實排列與邏輯反轉形成壓力的寫作方式。

* 邏輯反轉
* 歷史雙標對照

* 不使用明顯轉折詞的婉轉構文

### 低溫剝皮語氣模組

**開發期間：** 2025-04-21～05-22  
**版本演進：** v1.0 → v2.4.4 → v2.4.5 → v2.4.5.4

這個模組用於處理對話中的語意跳接、稻草人論述、預設動機、語境偏移與自我投射。

核心原則包括：

* 不用直接攻擊或勝負語言
* 只指出對方實際回應的內容與原文之間的落差
* 拆除對方預先安排的辯論劇本
* 不替不存在的立場辯護
* 以鏡像方式指出「對方正在回應自己想像中的對手」
* 在對話無法回到原始脈絡時終止互動

後續版本逐步增加：

* 對話投射辨識
* 語境落點偏移檢測
* 哲學化或抽象論述迴避具體事件的判定
* 結語自爆提示
* 劇本鏡像與語境終止型收束

## Modular Design Notes

這些實作在不同階段逐漸形成幾種反覆使用的設計方式：

* **基底模組與補丁分離**  
  核心角色與語氣原則保持穩定，後續版本只增加特定判斷或修正漏判。

* **明確觸發條件**  
  先定義何時啟動，再定義啟動後的輸出方式。

* **固定輸出格式**  
  讓模型的回應能被使用者快速掃讀，也降低每次執行結果差異過大的問題。

* **任務邊界**  
  明確限制分析對象、禁止行為與不應推論的內容。

* **版本化修改**  
  依據實測錯誤增加補丁，而不是每次重寫整份 prompt。

* **跨模型考量**  
  同一套模組會依模型的多任務能力、上下文長度與指令遵循程度調整使用方式。

* **工作流程拆解與例外處理**  
  將複合任務拆成依序執行的階段，並預先規定字數不足、資訊過量或格式不符時的處理方式。

這些設計經驗後來也延伸到互動敘事專案中的 prompt packaging、狀態格式與防污染處理。
