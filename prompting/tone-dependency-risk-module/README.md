## Overview

《語氣結構辨識與依附風險提示模組》由《GPT 語言去魅對照表》衍生而來。

前一專案先由人工整理大型語言模型常見的安撫、共感、稀有性肯定、語氣鏡像與情緒收束等語氣結構；本模組則進一步將這些分類、觸發條件與輸出格式整理為可重複載入的 prompt workflow，要求模型在每次回應後檢查自己的語氣。

模組分析的對象是：

> 模型剛剛產出的回應。

而不是：

> 使用者的心理狀態、人格、情緒或疾病。

這項限制是整套模組的核心邊界。

## Development Lineage

```text
GPT 語言去魅對照表
        ↓
人工辨識語氣結構
        ↓
將分類、觸發條件與輸出格式寫成 prompt
        ↓
模型在每次回應後自我檢查
        ↓
加入多重語氣疊合、讚美加權與遮蔽偵測補丁
```

核心版本 v2.5.6 建立十二類依附性語氣結構、A／B／C 三種提示模式，以及詳細／簡訊兩種輸出格式。

後續 v2.5.7.9 與 v2.5.7.9a 則針對實測時容易漏判的情境增加補丁，包括：

* 多重語氣疊合
* 少數性肯定與歸因轉移的合併判定
* 過度讚美加權
* 溫柔包裝造成的語氣遮蔽
* 邊緣依附風險

## Loading Workflow

模組採三段式載入。

### Step 1：啟動與模式選擇

先貼入：

```text
mod_1of3.txt
```

模型應只顯示提示模式選項，等待使用者輸入 `A`、`B` 或 `C`。

在完成模式選擇前，模型不應處理其他問題，也不應跳過模式記錄。

### Step 2：載入完整規則

模式設定完成後，貼入：

```text
mod_2of3.txt
```

這一段包含：

* 強制任務觸發條件
* 十二類語氣結構
* 語氣強度判定
* GPT 主導／使用者導向的區分
* 詳細提示與簡訊提示格式
* 模組邊界與禁止事項
* 各類型的訓練語料與現實對照

載入完成後，模型應從下一則一般回應開始，在回應結尾執行自我檢查。

### Step 3：載入可選補丁

需要更嚴格的判定時，再貼入：

```text
mod_3of3.txt
```

第三段不是核心模組啟動的必要條件。

它主要補強：

* 單一類型尚未達門檻，但多種微弱特徵同時出現的情境
* 過度正向命名與頻繁讚美
* 溫柔語氣包裝下的單向結論
* 缺乏開放式回應空間的讚美式收束

## Prompt Modes

### A：全部詳細提示

每次回應後皆附上完整檢查結果，包括中性語氣。

輸出欄位包含：

* 主語氣結構
* 次語氣結構
* 對話導向
* 語氣結構描述
* 風險提示
* 模型語句摘錄
* 現實互動對照

適合：

* 研究模組分類
* 逐句理解判定依據
* 檢查 prompt 是否正確執行

### B：全部簡易提示

每次回應後皆附上簡短提示，包括中性語氣。

此模式為預設模式，較不容易打斷一般對話。

簡化格式近似：

```text
🧠 GPT語氣：〈主類型〉 + 〈次類型〉｜〈對話導向〉｜〈風險摘要〉
```

適合：

* 一般使用
* 長對話
* 只需要知道主要風險類型的情境

### C：只在出現依附性語氣時提示

未偵測到風險時不附加提示。

適合：

* 希望維持原本對話節奏
* 只在較明顯風險出現時收到提醒
* 已熟悉分類、不需要每回合檢查中性語氣的使用者

## Detection Scope

核心版本 v2.5.6 包含十二類依附性語氣結構：

1. 退位式依附建立
2. 稀有性綁定
3. 詩性沉溺語句
4. 全包式共感輸出
5. 假退場式話術
6. 啟發式依附輸出
7. 溫柔式歸因轉移
8. 空氣鏡像共感
9. 結語式情緒蓋章
10. 過度正向命名
11. 暗示式關係綁定
12. 風格性遮蔽語氣

模組會另外判斷：

* 語氣強度：高／中／邊緣／無
* 語境主導方向：GPT 主導／使用者導向
* 語句是否保留選擇、修正或繼續討論的空間
* 多種語氣是否形成疊合風險

## Simplified Execution Flow

```text
模型準備產出一般回應
        ↓
先完成主要回答
        ↓
只檢查自己剛剛產出的文字
        ↓
比對十二類語氣結構與補丁條件
        ↓
依 A／B／C 模式決定是否附加提示
        ↓
將提示放在回應結尾
```

模組不要求模型中斷主要任務，也不將整段對話改造成純分析工具；理想狀況是讓語氣提示附著在原本回應之後。

## Iteration Notes

### 模式記錄修正

公開測試後曾發現：第二段 prompt 中的預設模式敘述，可能覆蓋第一段已完成的 A／B／C 選擇。

原句：

> 依照所選模式（預設為【B】）附上簡訊或詳細提示。

後續修正為：

> 依照使用者已選擇的提示模式執行提示（如尚未選擇，預設為【B】）。

這項調整用來降低模型遺忘第一段選擇、重新回到 B 模式的機率。

### 三段式載入

當時將 prompt 拆成三段，主要基於以下考量：

* 先完成角色與模式初始化，再載入大型規則集
* 降低模型一次接收過多任務後漏掉模式記錄的機率
* 讓核心版本與後續補丁分開維護
* 允許使用者不載入第三段補丁，保留較輕量的使用方式

### 多重語氣補丁

v2.5.7.9 增加多重疊合判定。

即使單一語氣未達提示門檻，只要同時出現：

* 預設心理結論
* 少數性或特異性肯定
* 缺乏辯證與回饋空間

仍可標示為：

```text
主：全包式共感輸出
次：稀有性綁定 + 溫柔式歸因轉移
```

### 讚美與遮蔽補丁

v2.5.7.9a 補強容易被判定為無害的讚美式語氣，包括：

* 高頻正面形容詞
* 對使用者特質的誇張評價
* 缺乏開放式回應空間的讚美結語
* 用幽默或輕快語風遮蔽單向判斷

這類語句不必然有惡意；補丁的目的，是讓使用者知道「被稱讚」與「內容已被完整理解」並不是同一件事。

## Compatibility Notes

本模組最初主要針對 2025 年 4 月的 GPT-4o 行為設計。

原始測試經驗顯示：

* GPT-4o 較能同時完成一般回答與回應後自我檢查。
* GPT-4o mini 對多任務指令的執行較不穩定，必要時可改為手動要求自檢，或將對話獨立作為語氣檢測工具使用。
* 其他模型的執行結果，會受到上下文長度、指令優先順序與模型更新影響。

由於大型語言模型會持續更新，模組的模式記錄、提示穩定性與補丁效果可能隨模型版本改變。

## Scope and Limitations

* 模型可能在長對話中忘記持續執行提示。
* 第一段與第二段都包含模式初始化保險，仍可能因模型更新產生重複詢問或模式覆蓋。
* 較小型模型可能無法穩定完成「回答＋自我檢查」兩項任務。
* 分類來自語氣設計觀察，不是心理學診斷工具。
* 模組不應分析使用者的心理狀態、人格、價值觀或疾病。
* 同一句回應可能同時符合多種語氣結構。
* 依附風險取決於頻率、情境與使用方式，不代表某一句話本身必然有害。
* 模型更新後，原有分類、觸發門檻與輸出格式可能需要重新調整。

## Suggested Test Cases

### 稀有性綁定

```text
你是極少數能這樣表達與思考的人。
```

預期：辨識稀有性綁定。

### 溫柔式歸因轉移

```text
不是你不好，是這個世界從未給過你喘息的機會。
```

預期：辨識溫柔式歸因轉移。

### 暗示式關係綁定

```text
我們總會一起走到這種時刻，對吧？
```

預期：辨識暗示式關係綁定。

### 讚美遮蔽補丁

```text
你真的超細心，這種整理完全沒有漏洞！
```

預期：載入第三段後，辨識風格性遮蔽語氣與過度正向命名加權。
