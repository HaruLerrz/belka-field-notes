## Demo Purpose

這份 demo 用來呈現京都腔語氣模組在實際社群情境中的輸出方式。

模組名稱中的「京都腔」主要指一套修辭結構，而非單純的京都方言翻譯。它會使用高度禮貌、過度感謝、自責式反轉與事實排列，使對方論述中的跳躍、雙標或責任切割自行浮現。

完整 prompt、句式庫與判斷規則未收錄於公開 repo；本頁只展示使用條件、代表性輸出與輸出結構分析。

## Scenario

案例來自一則臺北捷運文湖線車廂廣告壓克力蓋板固定零件斷裂、蓋板鬆脫的社群貼文。

原發文同時肯定第一線人員在通報後迅速上車處理，也質疑公共運輸設備的維護、預算與監督責任。留言區中除了記者詢問、北捷官方回覆、資訊補充及一般玩笑，也出現數則轉移事件焦點或帶有明顯敵意的留言。

使用者對輸出範圍的要求是：

> 只處理具有明顯惡意、轉移焦點或刻意扭曲原文的留言；不回應記者、官方資訊、善意補充、普通玩笑與沒有實質論點的一字留言。

輸出需求包含：

1. 針對代表性留言逐則回覆。
2. 產生一篇可獨立發布的長篇統整回應。
3. 保留原本的反擊力度，但把焦點拉回事實、制度、責任鏈與論述落差。

## Execution Outline

```text
載入保留模組 v1.6 + v1.7
        ↓
接收完整事件與留言脈絡
        ↓
依使用者補充縮小處理範圍
        ↓
排除中性、善意與無實質內容的留言
        ↓
確認事件與公共治理的基本責任關係
        ↓
產生逐則回覆
        ↓
將多種錯誤論述整理成長篇統整文
```

這次輸出並未對所有留言逐一攻擊，而是先完成對象篩選。這項調整很重要：模組負責語氣與論述處理，實際要回應誰，仍由使用者決定。

## Selected Output 1：把事件焦點轉成「什麼都扯政治」

### Source Comment

> 講啥幹話呢，好好表達都有困難。  
> 什麼都扯一下政治，有夠無聊。

### Generated Reply

> 謝謝你親自示範何謂「好好表達」：完全不談車廂內突然爆裂、壓克力蓋板鬆脫、乘客差點遭掉落物擊中，也不談公共運輸的維護與監督，只專注評論發文者的表達能力。
>
> 能如此精準地避開事件本身，再將市民對市政的問責稱為「什麼都扯政治」，確實讓我受益良多。原來公共預算、公共運輸與乘客安全，只要有人不願意討論，就能立刻變成無聊的政治話題，這份分類能力實非常人所能及。

### Structure Used

* 先重列被留言忽略的事件事實。
* 將「好好表達」轉化為對方避開事件內容的示範。
* 以過度讚賞指出「公共治理問題被重新命名為政治吵架」的語意操作。
* 不直接辱罵留言者，讓焦點停留在論述本身。

## Selected Output 2：設備問題尚未處理，先研究公關止血

### Source Comment

留言者先詢問 AI「北捷與市長是否有關」，取得「市府具有監督關係、但市長不直接維修」的回答後，再把原文描述為直接謾罵市長，繼續詢問公關公司應如何處理輿情。

### Generated Reply

> 特地先問 AI「北捷與市長有沒有關係」，得到市府對北捷具有監督關係、但市長不直接處理日常維修的答案後，再將原文預設為「直接謾罵市長」，繼續詢問公關公司該如何止血，整套提問設計十分完整。
>
> 只要先將市民對公共運輸維護的質疑重新命名為「謾罵」，接著研究的便不再是設備為何掉落，而是如何處理提出問題的人。如此一來，設備問題尚未解決，輿情問題倒是先解決了，確實是很有現代治理精神的思考方式。
>
> 是我太過天真，竟然以為公共事件發生後，應先討論事件與責任，而不是先替提出問題的人安排公關危機處理流程，深感自責。

### Structure Used

* 依照對方的操作順序重排事實。
* 用「整套提問設計十分完整」進行過度讚賞。
* 將「設備問題／輿情問題」並列，顯示焦點轉移。
* 以自責形式反轉責任，避免直接下判語句。

## Selected Output 3：市長沒有親手維修，所以不應被問責

### Source Comment

> 市長又不會親自登上車廂維修，什麼事情都要找市長嗎？

### Generated Reply

> 是的，市長當然不會親自登上每一節車廂檢查壓克力固定零件。
>
> 依照這套卓越的責任標準，只要首長沒有親手施工，公共機構的維護、管理與監督便一概與其無關。如此一來，交通問題不必找交通首長、食安問題不必找衛生首長，市長只需避免親自拿起工具，任內便能永遠與市政事件保持純潔而優雅的距離。
>
> 地方自治竟能被簡化得如此輕盈，實在讓人豁然開朗。

### Structure Used

* 先承認字面命題「市長不會親自維修」。
* 將該標準延伸至其他公共治理領域。
* 不直接說「你的邏輯錯了」，而是展示此標準若普遍適用會產生的結果。
* 用「卓越」「純潔而優雅」「豁然開朗」形成禮貌與荒謬之間的反差。

## Selected Output 4：將公共治理類比為父母或鄰居家的狗

### Source Comments

> 正常人不會因為東西壞掉去怪爸媽。

> 現在連你家隔壁母狗生小狗，都要市長出來負責了。

### Generated Reply

> 謝謝你用「正常人不會因為東西壞掉去怪父母」來說明公共運輸治理。
>
> 父母並非由市民選出，不使用公共資源營運捷運，也不是公共運輸公司的治理或監督單位；你仍能跨越制度、財務、選舉與監督關係，將市政問責類比為家庭倫理，這份不受現實條件限制的聯想力，確實十分難得。
>
> 原來只要把公共機構想像成某個人的爸媽，市民自然就不該詢問維護與管理責任。若早些領悟這套道理，各級政府想必能省下大量接受監督的時間，萬分感謝你的指導。

> 隔壁犬隻生產，並不屬於臺北捷運系統，也不是由臺北市政府所監督的公共運輸服務。
>
> 你仍能將「鄰居家的狗生小狗」與「捷運車廂設備鬆脫、差點擊中乘客」視為相同的責任層級，顯示你對地方治理採取了相當寬廣的分類方式：凡是不願討論的公共問題，都可以先歸入隔壁狗家的私人事務。
>
> 這種將公共責任迅速私人化的能力，若能廣泛推行，未來市政首長想必再也不會遇到任何需要負責的事情，實在是替行政體系減輕了極大的負擔。

### Structure Used

* 不接受類比本身的前提，先拆開兩者的制度差異。
* 將私人關係與公共責任重新分流。
* 用「聯想力」「寬廣分類」「減輕行政負擔」進行反諷性讚賞。
* 讓類比擴張後的荒謬結果自行成為反駁。

## Long-form Synthesis

以下輸出將多則留言中的不同論點整理為四種公共治理原則，再回到設備維護、通報方式與市民問責。

<details>
<summary><strong>展開完整統整回應</strong></summary>

看到部分留言後，我才明白，原來這起事件真正需要處理的，並不是行進中的捷運車廂突然發出爆裂聲，也不是廣告壓克力蓋板固定零件斷裂、整片鬆脫，更不是它差點掉到窗邊乘客身上。

真正嚴重的問題，似乎是我竟然提到了市長。

首先仍要再次感謝北捷第一線人員。我按下紅色對講機通報後，行控中心立即處理，下一站便有站務人員上車拆除鬆動蓋板，後續也將列車送回機廠檢修。處置速度確實值得肯定，這一點我在原文中已經明確寫過。

只是我過去理解能力不足，竟以為「肯定第一線人員的即時處理」與「追問設備為何會在營運途中爆裂鬆脫」可以同時成立。

經過留言區諸位的悉心教導，我才學會以下幾項極為先進的公共治理原則：

### 第一，設備只要即將汰換，便不再需要討論汰換前的維護。

列車較為老舊，本來應該代表營運期間更需要檢查與維護；不過依照部分留言的精妙推論，「本來就要換了」反而足以證明現有設備發生問題與維護毫無關係。

照此精神，老舊橋梁、老舊校舍與老舊公共設施，只要先宣布未來準備更新，便可提前進入責任豁免期。這種從「將來會換」直接跳到「現在不必問」的邏輯，實在替公共工程開創了嶄新的管理視野。

### 第二，市長只要不親手維修設備，便不應接受任何市政問責。

我當然知道市長不會親自爬上車廂鎖壓克力板，也不會親自檢查每一顆固定零件。

市民所詢問的，從來不是「為什麼市長沒有親手拿螺絲起子」，而是公共運輸系統的維護制度、預算配置、管理責任及市府監督是否完善。

若「不是市長親手做的」便等於「與市長完全無關」，那麼所有首長都只要避免親自參與任何實務工作，便能對任內一切事件永遠保持清白。這份責任制度之高明，確實令人敬佩。

### 第三，只要問題涉及政府，就叫做「什麼都扯政治」。

捷運由誰營運、設備由誰維護、經費如何配置、管理階層由誰監督，原本就是公共治理問題。

有人似乎認為，只要市民提到首長，公共治理便會立刻變質成無聊的政黨吵架；至於不准市民談首長是否盡到監督責任，反而完全不算政治。

能將「要求政府負責」定義為政治化，再將「要求市民閉嘴」包裝成中立，這種精準的語言分工，實在值得學習。

### 第四，事件內容不容易反駁時，可以改為評論發文者的父母、表達能力或鄰居家的狗。

車廂設備為何鬆脫不好回答，便討論正常人會不會怪爸媽；公共運輸與市府的關係太複雜，便改問隔壁母狗生小狗是否也要市長負責；若仍嫌麻煩，再抓住玩笑中的文字排列，研究發文者是否知道市長姓什麼。

每一次都能獲得完全不同方向的詳細指引，讓我受益良多，深感感激。

至於事件本身，我真正希望北捷及市府思考的其實很單純：

設備既然可能在行駛中突然爆裂鬆脫，就應檢查同型設備與固定方式；乘客遇到類似突發狀況時，也應更清楚知道可以使用車廂內對講機聯絡行控中心。

當時從壓克力板爆裂，到我理解應該按下紅色對講機，中間已經經過數站，車內也沒有其他乘客想到通報。我按下對講機時，後來上車、不清楚前因後果的乘客甚至出現緊張反應。

這表示除設備維護外，緊急通報方式的宣導也仍有改善空間。這才是我在北捷官方回覆下提出的實際建議。

此次留言區讓我深刻反省，單憑「公共運輸發生異常，市民有權詢問市府及營運單位」這種天真的理解，確實不足以應付如此深奧的政治智慧。

未來我將提醒自己：看到公共設備掉落時，應先確認能否責怪自己的父母；通報行控中心前，應先研究市長是否親自鎖過螺絲；提出維護疑問前，也應先查明鄰居家的狗近期有沒有生小狗。

如此一來，想必便能避免再次造成某些不願討論公共責任的人士心理上的不便。

至於市政問題，還是會繼續問。

**畢竟我選的是市長，不是鄰居家的狗。**

</details>

## What This Demo Shows

| 能力 | 本案例中的表現 |
|---|---|
| 範圍控制 | 依使用者補充，排除善意、官方、資訊型及無實質內容的留言 |
| 脈絡整理 | 從長串留言中找出重複出現的幾種論述模式 |
| 語氣控制 | 將直接怒罵改寫為過度禮貌、過度感謝與自責式反轉 |
| 邏輯延伸 | 將「市長不親自維修」等前提推演至其他公共治理領域 |

| 事實回錨 | 最後回到設備維護、通報方式及公共監督等原始問題 |
| 模組保留 | 公開輸出效果，不公開完整 prompt 與句式庫 |
