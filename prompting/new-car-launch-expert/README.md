# 新車發表專家

本頁整理我自 2024 年起使用的「新車發表專家」Custom GPT。這組工作型 prompt 用於台灣市場的新車發表影片，串接資料搜尋、規格整理、使用者確認、靜態分鏡與新聞口白。

## Project Context

新車發表採訪常有固定限制：

* 拍攝時間有限
* 現場以靜態展示為主
* 車輛可以啟動並操作電子配備，但通常無法實際行駛
* 原廠資料、台灣車型規格與媒體報導可能存在版本差異
* 分鏡必須配合現場能拍到的內容
* 口白需要保留具體數字，同時避免過度公關化

新車發表專家將這些條件整理成固定工作流程，減少每次重新交代來源、規格欄位、拍攝限制與輸出順序的成本。

## Core Workflow

```text
確認查詢時間與台灣市場車型
        ↓
搜尋官方資料與本地媒體來源
        ↓
整理燃油／電動車對應規格
        ↓
依欄位清單進行完整度檢查
        ↓
等待使用者確認資料
        ↓
產生靜態拍攝分鏡
        ↓
等待使用者調整與確認
        ↓
依實際素材規劃新聞式口白
```

這套流程保留兩個人工確認點：

1. 規格資料確認完成後，才進入分鏡。
2. 分鏡確認完成後，才進入口白。

資料錯誤或現場限制可以在前一階段先修正，避免一路帶進後續剪輯。

## Instruction Design

### Source and Search Rules

各版本都要求模型先搜尋，再整理資料。來源順序以台灣官方汽車品牌網站為優先，本地汽車媒體作為交叉查核與補充。

主要規則包含：

* 強制搜尋
* 優先採用台灣市場資料
* 參考多個來源
* 標明舊年份或海外版本資料
* 提供具體來源
* 避免把查證工作重新丟回使用者

### Vehicle Data Schema

燃油車與電動車使用不同欄位。

燃油車常見欄位：

* 排氣量
* 最大馬力與扭力
* 油箱容量
* 油耗
* 行李廂空間
* 輪圈、燈組、安全與座艙配備

電動車常見欄位：

* 馬達輸出
* 電池容量
* 續航里程
* AC／DC 充電規格與時間
* 充電接口
* 行李廂空間
* 輪圈、燈組、安全與座艙配備

### Static Filming Boundary

後期版本明確設定拍攝條件：

* 車輛可發動
* 電子配備可操作
* 車輛無法行駛
* 需要行駛才能展示的安全系統或動態功能，標示為使用原廠提供畫面

分鏡不指定攝影器材，也不預設現場場景；內容集中在實際需要拍到的車輛部位與操作項目。

### Self-check and Retry

2.3 起加入完整度評分：

1. 依燃油車或電動車欄位逐項檢查。
2. 另計來源年份、網域與具體引用。
3. 未達門檻時重新搜尋缺漏項目。
4. 避免以「可自行參考」取代實際資料。

這項設計用於提醒模型補齊欄位。最終資料仍需人工核對，評分本身不等同事實查證。

### 1.0

初版建立完整的階段控制：

1. 提供車型資料
2. 等待規格確認
3. 產生靜態畫面分鏡
4. 等待分鏡確認
5. 討論各畫面口白

同時建立台灣市場優先、官方資料優先與強制搜尋等基本規則。

### 2.0

2.0 保留原有五階段架構，主要擴充第五階段的口白規格：

* 具體排氣量、馬力、油耗與續航數字
* 行李廂空間
* 燃油版與電動版共同標配
* 購車優惠
* 電動車 AC／DC、快充與慢充資訊

這一版開始把資料整理結果更完整地帶入最後口白。

### 2.3

2.3 加入自我檢查與重新搜尋條件。

新增內容包含：

* 燃油車與電動車分開評分
* 行李廂、車色、動力、安全、座艙與便利配備欄位
* 引用年份、台灣網域與具體來源評分
* 低於 80 分時重新搜尋缺漏資料
* 六階段流程
* 口白結尾加入售價與優惠方案

此版本的電動車評分清單末尾保留一個未完成的「23」項目，後續在 2.3.5 修正。

### 2.3.5

2.3.5 補強規則邊界與資料欄位：

* 回答語系固定為繁體中文
* 以查詢時間判斷應搜尋當年度或下一年度車型
* 台灣官方資料優先，其他本地車訊作為補充
* 動力欄位加入扭力
* 座艙欄位加入空調、音響、儀表、電控座椅與材質
* 評分公式加入實際計算例
* 修正電動車清單的未完成項目
* 說明靜態展示可發動但不可行駛
* 動態功能改以原廠提供畫面處理

* 固定角色與任務範圍

## Legacy Constraints

這些版本保留了當時模型與工作需求下形成的限制：

* 年份曾直接寫成 2024，長期使用需要改為動態日期。
* `.tw` 網域限制有助於聚焦台灣市場，也可能排除採用全球網域的台灣官方頁面。
* 固定欄位可以提升完整度，資料來源缺漏時仍可能誘發模型補寫不存在的細節。
* 自我評分適合做完整度提醒，無法代替來源核對。
* 指令長度隨版本持續增加，後續可拆成搜尋、資料結構、分鏡與口白等模組。
